# PGS Hub Cloudflare security policy

This is a proposed edge policy, not an applied Cloudflare configuration. Confirm plan availability, observe real traffic, and tune values before enforcement. All numeric values below are **INITIAL ROLLOUT VALUES**, not permanent universal truths.

## Deployment principles

- Cloudflare is layer 1; NestJS Throttler remains layer 2 at 120 requests per 60 seconds per route handler and canonical client IP unless environment values are deliberately changed.
- Start custom rate rules in Log mode where the plan supports it, review Security Events/analytics, then move narrowly to Managed Challenge or Block. Rate-limit counters can be approximate, so application authorization remains mandatory.
- Do not use country, browser, or user-agent alone to block staff. Do not treat IP as identity.
- Exclude verified Cloudflare internal mechanisms if required, but never blanket-skip authenticated traffic from WAF inspection.

## Cache policy

Create an explicit Cache Rule for the entire `api.<company-domain>` hostname with action **Bypass cache**. Keep `/api/v1/health` uncached too. Never apply “Cache Everything” to the API. This protects Authorization-bearing requests, profiles, attendance, payroll, finance, admin, document signed URLs, chat, and all other dynamic responses even if a future rule changes normal authorization-based cache behavior. Web caching stays with Vercel because the web hostname is DNS Only. Reference: [Cache Rule settings](https://developers.cloudflare.com/cache/how-to/cache-rules/settings/).

## WebSocket compatibility

Cloudflare supports proxied WebSockets, while WAF/rate controls primarily inspect the initial upgrade. Preserve `/socket.io/` upgrades and avoid low burst limits that break reconnect storms. The app namespaces remain `/chat`, `/notifications`, and `/project-workspace`; CORS remains exact `WEB_URL`, and Supabase token authentication is required. Source TCP IP is never authentication. See [WebSockets](https://developers.cloudflare.com/network/websockets/).

## Cloudflare Access decision

**Option A — default V1:** no Cloudflare Access in front of the whole API. Use WAF, rate limiting, Supabase/application auth, and application authorization.

**Option B — future:** use Access only for separately identified internal operational/admin tooling after browser CORS, preflight, service-token, and WebSocket behavior is designed and tested. Access adds a `CF_Authorization` cookie/token flow and can complicate cross-origin APIs; do not double-auth the entire app without approval. References: [Access authorization cookie](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/) and [Access CORS guidance](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/cors/).

## Turnstile review

Turnstile is a good future control for public login, sign-up/invite acceptance, password-reset request, and similar unauthenticated forms. The current web pages call Supabase Auth directly from the browser, so there is no trusted application-controlled server validation point. Do not add a cosmetic client-only widget. A future design must introduce an approved server/Edge validation endpoint, validate every token server-side, and only then perform/authorize the action. Tokens are short-lived and single-use. Normal authenticated API calls must not require Turnstile. References: [Turnstile setup](https://developers.cloudflare.com/turnstile/get-started/) and [server-side validation](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/).

## Security headers

NestJS Helmet remains authoritative for API response headers: production HSTS, CSP, `frame-ancestors 'none'`, and `object-src 'none'`. CORS remains application-controlled with the exact `WEB_URL`; do not create Cloudflare header transforms that duplicate, strip, or weaken these headers. API CSP `connect-src` currently contains self, exact web URL, and Supabase URL. Before any web-side CSP is tightened, explicitly retain HTTPS/WSS connectivity to the API hostname and Socket.IO. Cloudflare must pass WebSocket upgrade headers.

## Operational rollback

Every WAF and rate rule has an independent disable/Log rollback. Cache rollback means retain or restore API Bypass, never Cache Everything. Tunnel/connector/API rollbacks are in the Tunnel runbook. Do not use a database rollback for a Cloudflare or network failure, and never expose the origin automatically when an edge control fails.
