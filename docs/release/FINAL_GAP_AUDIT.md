## 2. Background processing (`WorkflowAutoTaskScheduler`) — reviewed

- Event path creates auto-tasks right after a client approval (system actor: project manager, else admin). Duplicates are prevented by the DB function `workflow_create_primary_task` with an item lock and a partial unique index, not by the application.
- The safety-net sweep runs every `WORKFLOW_AUTOTASK_SWEEP_MS` (default 60 s; `0` disables; off when `APP_ENV=test`). It uses keyset pagination with a page cap, keeps going when one workflow fails, skips overlapping runs, and a failed run is retried by the next tick. These behaviours have unit tests in `workflow-auto-task-and-client-approvals.spec.ts` (including "more than 200 ready items" and "recovers after an incident").
- Limits that matter for operations: the timer is **in-process** (cPanel Passenger can stop an idle process, which also stops the sweep until the next request or health ping); with several instances each runs its own sweep (safe because of the DB guard). An external uptime monitor on `/api/v1/health` is therefore part of the design (`PRODUCTION_PREFLIGHT_CHECKLIST.md` 5.3). **NOT VERIFIED on production.**

- Concurrent writes beyond the cases in Flows 04 (approval) and 06 (payments).
- Kanban keyboard operation (drag only), touch-target size (<44 px for `sm`/`md` buttons), text below 12 px (OI-15/OI-16).
- Tablet/mobile prototype links in Figma (G-06) and the full Figma 18-item acceptance (`docs/ux/FIGMA_HANDOFF_18_CHECKLIST.md`).
